# 批量改色：原生可编辑工程

## 本次变更

“生成全部”不再烘焙和回传PNG，而是求解原生调整层配方，在用户明确选择的蒙版组内，每个SKU新增一个穿透子组。曲线、颜色填充、可选颜色、渐变映射、通道混合器、色相/饱和度均为Photoshop原生图层，允许双击继续修改。父组蒙版与原始图层保留，首个SKU显示，其余隐藏。不自动保存或覆盖用户PSD。

四模式基础结构（下列顺序为从底到顶）：

| 模式 | 原生匹配图层 |
| --- | --- |
| mode1 | 明暗曲线（明度）→ RGB曲线（颜色）→ 75%纯色填充（颜色） |
| mode2 | 明暗曲线（明度）→ 绝对可选颜色→辅助颜色填充 |
| mode3 | 明暗曲线（明度）→渐变映射 |
| mode4 | 明暗曲线（明度）→通道混合器 |

手动对比度/阴影/高光在基础匹配层下方，手动色相/饱和度及可选着色层在上方。只创建实际启用的手动调整层。

目标蒙版组须使用“穿透”混合模式，否则会提示用户修改，不擅自改变原组属性。旧版桥接v67的像素贴回接口不接收新配方；原生输出要求v68，版本不符会明确拦截，不回落成品图片。

- 宿主模拟：在原组内为每SKU创建子组；只创建调整层，不调用putPixels；首组可见其余隐藏；原层和父蒙版保留。
- UI事件：参考图上传自动分析、独立模式选择、生成按钮传递原生配方而非PNG、错误反馈与卡片初始化。

### 真实Photoshop测试

通过本机Photoshop的Action Manager调用同一份描述符，在独立128×128 RGB/8-bit测试文档中创建并读回：

| 类别 | 实际Photoshop类型 |
| --- | --- |
| 曲线 | LayerKind.CURVES |
| 纯色填充 | LayerKind.SOLIDFILL |
| 色相/饱和度 | LayerKind.HUESATURATION |
| 可选颜色 | LayerKind.SELECTIVECOLOR |
| 渐变映射 | LayerKind.GRADIENTMAP |
| 通道混合器 | LayerKind.CHANNELMIXER |

真实测试发现渐变映射创建类名必须是gradientMapClass，已修正。

进一步在真实PS里建立带像素蒙版的父组，创建4个SKU子组：mode1和mode2各8个原生调整层，mode3和mode4各7个原生调整层（测试参数启用了部分手动调节）。保存为新PSD后重新打开，检查4个子组及可见性，全部通过。原用户文档没有执行保存、覆盖或丢弃操作。

## 验证边界

- 助手已验证真实PS的六类原生调整层和PSD保存重开；插件UXP分组写回另有模拟宿主测试。用户已反馈实际测试没有问题；助手未独立复验用户当前服装工程的整套四SKU界面流程。

- 不声称与Web原项目所有算法/交互逐像素等价，也不声称复杂PSD全量无损往返；本实现只追加原生调整层，不解析和重编码源PSD。
